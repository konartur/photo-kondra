# PF-UX-01 — Візуальний вибір фото

**Статус:** Реалізовано, перевірки відкладено.
**Залежить від:** Немає.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: frontend/app/dashboard/portfolio/editor-fields.tsx; frontend/app/dashboard/portfolio/portfolio-media-library.tsx.

## Обсяг

1. Створити спільний діалог вибору фото з сіткою мініатюр для одного й кількох зображень. Поточне поле показує мініатюру та «Обрати фото» / «Замінити».
2. Показувати вибір рамкою, позначкою та доступним станом. Підтвердження — «Обрати фото» / «Додати N фото»; закриття скасовує лише поточний вибір.
3. Додати стани завантаження, порожнього списку та помилки. PROCESSING/FAILED пояснювати, але не дозволяти підтверджувати.
4. Передбачити підвантаження сторінок, виключення вже доданих фото та переданий ззовні ліміт.
5. Підтримати клавіатуру, Escape, утримання фокуса в діалозі та повернення до кнопки відкриття. На телефоні діалог повноекранний. Використати захищені похідні зображення й lazy loading.

## Критерії приймання

- [ ] Компонент підтримує single/multiple вибір без завантаження оригіналів.
- [ ] Готове фото впізнається за мініатюрою; назва файла допоміжна.
- [ ] Закриття без підтвердження не змінює поле.

## Межі

Інтеграція всіх полів і завантаження файлів — наступний тікет.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.

## Запис виконання

- Зміни: додано спільний `PortfolioPhotoPicker` з типізованими single/multiple props, мініатюрами поточного значення, локальним вибором до підтвердження, лімітом, виключенням уже доданих фото та станами loading/error/empty. Fetching, retry й пагінацію передає викликач через props; компонент не створює власного API-клієнта.
- Файли: `frontend/app/dashboard/portfolio/portfolio-photo-picker.tsx`, `frontend/app/dashboard/portfolio/portfolio-photo-picker.module.css`.
- Доступність: native modal dialog у portal за межами форми, Escape/скасування, початковий фокус на скасуванні й повернення до кнопки відкриття; вибір позначено рамкою, текстом і aria-pressed. Недоступні плитки лишаються доступними для фокуса з aria-disabled і поясненням. Mobile: повний екран, внутрішня прокрутка та safe area.
- Інтеграція: компонент підготовлений для PF-UX-02; чинні dropdown-поля ще не замінено відповідно до меж цього тікета. Шляхи зображень перевіряє чинний AdminImage; оригінали не використовуються.
- Відкладені перевірки й ризики для PF-UX-14: single/multiple confirm/cancel; Escape/Tab/повернення фокуса, включно з React Strict Mode; оновлення статусів фото після вибору; вибрані ID поза завантаженими сторінками; retry і pagination без скидання вибору; зміна ліміту/used під час відкритого діалогу; disabled у формі; desktop/mobile/ландшафт/темна тема/масштабування тексту. Написання тестів, запуск lint/typecheck/build і браузерне QA не виконувалися за вказівкою власника.
- Огляд: виконано читання коду й diff; критерії приймання вище залишаються непідтвердженими до PF-UX-14.
- Блокери: на етапі огляду коду не виявлено; працездатність ще не перевірена.
