# PF-UX-02 — Єдина фотобібліотека та завантаження у виборі фото

**Статус:** Заплановано.
**Залежить від:** PF-UX-01.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: editor-fields.tsx, editor-forms.tsx, portfolio-media-library.tsx, portfolio-workspace.tsx; backend media list DTO/service — лише якщо потрібен серверний пошук.

## Обсяг

1. Замінити всі списки назв фото спільним вибором: hero desktop/mobile, фото фотосесії, обкладинка та фото історії, фон, фото добірки, фото поширення.
2. Залишити повну фотобібліотеку лише в її власному розділі, прибрати дублювання над формами.
3. Використати спільний upload-процес у бібліотеці та діалозі: direct PUT, підтвердження, обробка, повторна спроба. Новий файл після готовності доступний без закриття діалогу; поточний вибір зберігається.
4. Додати пошук за назвою файла з пагінацією. Пошук має охоплювати бібліотеку, а не лише завантажені сторінки; за потреби мінімально розширити чинний list API, Swagger і query keys.
5. При заміні файла зберігати контекстні alt і кадрування; передбачити недоступний раніше вибраний файл без тихої підміни.

## Критерії приймання

- [ ] У редакторі немає вибору фото лише за назвою файла.
- [ ] Завантаження і вибір працюють в одному діалозі зі збереженням стану.
- [ ] Пошук і наступні сторінки не приховують вибрані значення.

## Межі

Не змінювати модель Photo Cloud або правила приватного сховища.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.
