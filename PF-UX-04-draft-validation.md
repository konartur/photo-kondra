# PF-UX-04 — Збереження неповної чернетки та готовність до публікації

**Статус:** Заплановано.
**Залежить від:** PF-UX-03.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: backend/src/portfolio: draft DTO, admin/publication services, readiness mapping; frontend requiredDraftFields та помилки; контрактні документи.

## Обсяг

1. Розділити перевірку допустимого введення під час save і повноти під час publish. Дозволити незавершені тексти, переклади та відсутні зображення в чернетці.
2. Зберегти whitelist, типи, максимальні довжини/розміри, ownership, версійність та перевірки безпеки. Відсутнє значення й некоректне значення розрізняти явно.
3. Publish і надалі вимагає повноти uk/en, готових фото, чинних залежностей та ліміту фото. Public DTO отримує лише валідний опублікований snapshot.
4. Повертати структуровані причини неготовності з шляхами полів/мовою через наявні DTO або мінімальне сумісне розширення.
5. Узгодити Prisma JSON, runtime DTO, документацію, frontend input types і чинний workflow контрактів. Будь-яку необхідну міграцію робити additive.

## Критерії приймання

- [ ] Неповна, але допустима чернетка зберігається.
- [ ] Неповні дані не можуть потрапити в public snapshot.
- [ ] Причини блокування публікації можна пов’язати з полем і мовою.

## Межі

Не послаблювати public-контракти чи авторизацію. Залежні від build генератори й перевірку згенерованих артефактів виконати у PF-UX-14.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.
