# PF-UX-04 — Збереження неповної чернетки та готовність до публікації

**Статус:** Реалізовано, перевірки відкладено.
**Залежить від:** PF-UX-03.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: backend/src/portfolio: draft DTO, admin/publication services, readiness mapping; frontend requiredDraftFields та помилки; контрактні документи.

## Обсяг

1. Розділити перевірку допустимого введення під час save і повноти під час publish. Дозволити незавершені тексти, переклади та відсутні зображення в чернетці.
2. Зберегти whitelist, типи, максимальні довжини/розміри, ownership, версійність та перевірки безпеки. Відсутнє значення й некоректне значення розрізняти явно.
3. Publish і надалі вимагає повноти uk/en, готових фото, чинних залежностей та ліміту фото. Public DTO отримує лише валідний опублікований snapshot.
4. Повертати структуровані причини неготовності з шляхами полів/мовою через наявні DTO або мінімальне сумісне розширення.
5. Узгодити Prisma JSON, runtime DTO, документацію, frontend input types і чинний workflow контрактів. Будь-яку необхідну міграцію робити additive.

## Критерії приймання

- [ ] Неповна, але допустима чернетка зберігається.
- [ ] Неповні дані не можуть потрапити в public snapshot.
- [ ] Причини блокування публікації можна пов’язати з полем і мовою.

## Межі

Не послаблювати public-контракти чи авторизацію. Залежні від build генератори й перевірку згенерованих артефактів виконати у PF-UX-14.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.

## Запис виконання

- Зміни: frontend save більше не вимагає завершених текстів, uk/en, фото або ціни. Порожній список фото дозволено у draft DTO/API. Порожня адреса налаштованого контакту дозволена в чернетці; непорожня адреса досі перевіряється на безпечний email/HTTPS-профіль. Відсутні обов’язкові ключі, null неправильного типу, некоректні UUID, перевищення довжин, дублікати та неправильні focalPoint/price залишаються помилками введення.
- Межа даних: адреса (slug) і дійсний serviceId історії залишаються обов’язковими для збереження — це чинні unique/check/FK інваріанти. Їх не замінюємо вигаданими значеннями. Міграції та зміна Prisma-моделі/JSON не потрібні: локалізовані тексти вже дозволяють порожні рядки, а зображення — явний null. До створення історії потрібні лише її адреса й фотосесія; повнота контенту перевіряється пізніше.
- Публікація: додано `portfolio-readiness.ts` з причинами за шляхами полів і мовою. Перевіряються uk/en, зображення й alt, SEO, бронювання/ціна, контакти, добірки, щонайменше одне фото історії та union-ліміт 10. `prepareSnapshot` збирає непубліковані залежності та media без READY/похідних у тій самій транзакції до запису snapshot. Published read DTO не послаблювалися; існуюча публікація не змінюється через неповну чернетку.
- Безпека медіа: чернетка може посилатися на власний UPLOADING/PROCESSING/FAILED файл; ownership і невидалений стан перевіряються при save. Чужий/відсутній/видалений файл відхиляється однаковим 404. Publish і preview вимагають READY та похідних. UI picker досі дозволяє новий вибір лише готових фото.
- Помилки: 409 PORTFOLIO_NOT_READY та PORTFOLIO_STORY_SERVICE_UNPUBLISHED можуть містити `errors: [{ field, code }]` у чинному envelope. Global filter передає лише перевірені шляхи/коди, максимум 50, тільки для portfolio admin routes; значення, media IDs та storage keys не повертаються. Групові помилки підсвічують відповідний контрол. Preview передає отримані поля редактору для підсвічення та фокуса.
- Файли: backend `portfolio-readiness.ts`, `portfolio-publication.service.ts`, `portfolio-admin.service.ts`, `dto/admin-input.dto.ts`, `dto/admin-response.dto.ts`, `common/api-exception.filter.ts`, `setup-app.ts`, `scripts/generate-portfolio-contracts.mjs`; frontend `portfolio-workspace.tsx`, `portfolio-preview.tsx`, `editor-fields.tsx`, `editor-forms.tsx`.
- Контракти: runtime Swagger і генератор документують розширений error envelope для 400/409. Генерацію OpenAPI snapshot/frontend declarations та --check відкладено до PF-UX-14, бо workflow запускає build. Generated files вручну не змінювалися; чинні frontend response types підтримують nullable фото й errors, shape input/response не змінено.
- Відкладені перевірки PF-UX-14: мінімальна чернетка фотосесії/історії, settings без фото й перекладу, порожній список фото, порожній контакт проти некоректного непорожнього профілю, whitelist/null/UUID/межі, чужі/deleted/processing медіа, 409 із точними шляхами без значень, uk/en/SEO/ціна/alt/добірки, неопубліковані залежності, блокування порожньої історії та rollback snapshot, конкурентні save/publish, видимість попереднього snapshot після неповного save, підсвічення вкладених і згорнутих полів, preview 409, контрактна генерація й усі required checks.
- Огляд: виконано читання коду та diff. Тести, lint/typecheck/build і браузерне QA не запускалися за вказівкою власника; критерії приймання ще не підтверджені.
- Блокери: на етапі огляду коду не виявлено; працездатність ще не перевірена. PR залежить від PF-UX-03, злиття виконує власник.
