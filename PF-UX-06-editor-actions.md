# PF-UX-06 — Єдина панель збереження, перегляду й публікації

**Статус:** Реалізовано, перевірки відкладено.
**Залежить від:** PF-UX-05.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: portfolio-workspace.tsx, portfolio-preview.tsx: підключення дій; спільний стан editor.

## Обсяг

1. На desktop закріпити панель під глобальною навігацією: назва і статус ліворуч, дії праворуч. На mobile — статус над формою й нижня панель із safe area та відступом під контент.
2. За таблицею станів плану виділяти одну основну дію: «Зберегти чернетку» при dirty; «Опублікувати зміни» після save; для чистої публікації — другорядне «Відкрити сайт».
3. «Зберегти й переглянути» очікує повного успішного save та відкриває саме повернуту версію. Після помилки preview не відкривати. «Переглянути чернетку» для чистого стану показує збережену версію.
4. Показувати «До публікації залишилось» з переходами до полів; причина неактивної дії доступна і без hover. Розрізняти unsaved та unpublished.
5. Прибрати номери версій з основного тексту, архівацію перенести в меню з підтвердженням. Конфлікти вирішувати зі збереженням правок; до розв’язання блокувати подальші мутації.
6. Пояснити область публікації: лише відкритий запис. Залежності фотосесії/історії/головної показувати явно. Захистити від повторного submit.

## Критерії приймання

- [ ] Усі дії редактора зібрані в одному місці без повторних кнопок у секціях.
- [ ] Користувач бачить, що збережено, що вже на сайті та що блокує публікацію.
- [ ] Панель не перекриває поля, помилки й клавіатурний фокус.

## Межі

Автозбереження не додавати. Новий вигляд сторінки preview — PF-UX-07; тут використовувати чинний приватний preview.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.

## Запис виконання

### Зміни

- Одна панель містить save, preview і publish; кнопки прибрано з форми та нижнього preview. При незбережених правках основна дія — save, після save — publish, для чистої публікації є другорядний «Відкрити сайт». Desktop: sticky-панель після глобальної навігації; mobile: статус над формою й fixed bottom дії з safe area.
- ResizeObserver вимірює панель і блок кнопок; CSS використовує їхню висоту для нижнього відступу та scroll-margin полів/details/preview. Окрема мобільна верстка не дублює кнопки чи їхній стан.
- Save-and-preview спершу виконує повний save, потім запитує preview за ID і версією повернутого запису. Несумісна draftVersion стає явним conflict без показу чужого preview. Після помилки старий preview не відкривається; успішно збережена чернетка залишається збереженою навіть при помилці наступного preview.
- Ключ редактора змінюється при навігації, але зберігається при new→id. Query cache заповнюється до зміни ID; local state/повідомлення/preview зберігаються у тому самому Editor. Мова preview змінюється через спільний run/pendingRef; змінена незбережена форма явно позначає попередній перегляд як збережену версію.
- «До публікації залишилось» показує людські назви полів, переклад, media processing і непубліковані залежності. Дані медіа/залежностей читаються окремо за ID через TanStack Query, тому перевірка не обмежена першою сторінкою list. PROCESSING оновлюється до готовності; errors мають повторну перевірку. Перехід відкриває details і фокусує конкретне поле або відповідний груповий контрол. Локальні підказки не замінюють авторитетну перевірку publish API.
- Стани unsaved/unpublished/archived/published розділено, область публікації пояснено. Архівація з підтвердженням і технічні версії — у «Ще». Конфлікт блокує save/publish/archive; доступні звірка й явне прийняття збереженої версії або збереження власних правок у формі. Технічне порівняння приховано в додаткових деталях.

### Перевірки та ризики

- Виконано читання актуального коду та огляд diff. Тести, lint/typecheck/build і браузерне QA не запускалися за вказівкою власника. API/DTO не змінювалися, тому нова генерація контрактів для цього тікета не потрібна.
- PF-UX-14: стани кнопок для new/dirty/saved/published/archived/conflict; один submit поза формою через form ID; порожні alt не блокують save; save-and-preview для new та existing; failure save/preview окремо; exact returned version і конкурентна зміна; збережений local state після new→id; мова preview; старий preview при нових правках; недоступні медіа/залежності поза першою сторінкою; polling READY; nested fields/details і keyboard focus; повторні кліки й pendingRef; responsive/375px/ландшафт/text zoom/темна тема/safe area/мобільна клавіатура; реальна висота панелі не перекриває поле чи останній контент.
- Preview зберігає чинне представлення контенту. Повноцінний вигляд сторінки сайту та перемикач ширини — PF-UX-07. Timeout reconciliation і решта відкладених зауважень #35 залишаються у PF-UX-14.
- Блокери: на етапі огляду коду не виявлено; працездатність і критерії приймання ще не підтверджені.

### Правки рев’ю PR #36

- Обидва набори readiness queries мають staleTime 60 с і не оновлюються при фокусі вікна. READY-медіа та залежності з завантажених списків використовуються без detail-запитів; polling лише PROCESSING. Summary залежності не записується в кеш повного редактора.
- Помилка preview неповної чернетки явно підтверджує save й відкриває чекліст; замість загальної інвалідації оновлюються поточний запис і медіа. Для новоствореного запису використовується ID, отриманий після save.
- Недоступна публікація залишається доступною для фокуса через aria-disabled: натискання пояснює причину без мутації. Причина також показана під статусом у toolbar.
- Додано fallback прокрутки й повідомлення для відсутнього поля. Закриття preview залежить лише від pending. Короткі назви дій доповнено докладними aria-label; прибрано довільне розбиття слів на мобільному.
- `deriveEditorStatus` винесено в чисту функцію; редагування знімає лише помилки змінених полів. `publicUrl` кодує slug і читає локаль зі спільних налаштувань публічної головної (поточне значення uk збережено).
- CSS має fallback кольорів рамок/фону. Глобальна навігація не sticky, тому desktop top: 1rem залишено. Винесення EditorToolbar (пункт 11) відкладено в окремий рефакторинг; поведінкові перевірки й юніт-тести додано у PF-UX-14.
- Додаткові файли: `portfolio-editor-state.ts`, `lib/portfolio/public-url.ts`, `lib/portfolio/site-settings.ts`, `app/page.tsx`; оновлено PF-UX-00 і PF-UX-14.
- Перевірки на прямий запит рев’ю: Prettier змінених frontend-файлів та цільовий ESLint пройшли. `PHOTO_CLOUD_NEXT_DIST_DIR=.next-pr36-verified npm --prefix frontend run build` пройшов, включно з TypeScript. Перший build у sandbox завершився Turbopack process error; повтор поза sandbox успішний. Build показав чинне попередження про кілька lockfile.
- Headless Chromium із production CSS: 1280/375 px, light/dark — рамка toolbar 1 px, на mobile рамка actions 1 px; фон непрозорий, кольори тексту/рамок відрізняються від фону. Переглянуто скриншоти light desktop і dark mobile. Це ізольована перевірка CSS, не наскрізний тест редактора. Локальні артефакти — ігнорована `frontend/test-results/pr36-*`; мережеві/поведінкові сценарії не запускалися.
