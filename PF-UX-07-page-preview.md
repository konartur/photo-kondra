# PF-UX-07 — Приватний перегляд як сторінка сайту

**Статус:** Заплановано.
**Залежить від:** PF-UX-06.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: portfolio-preview.tsx; frontend/app/_portfolio; admin preview API/mapper і BFF за потреби.

## Обсяг

1. Винести preview з нижньої частини довгої форми в окремий режим із «Чернетка · бачите лише ви» та «Повернутися до редагування».
2. Повторно використати компоненти публічної сторінки через presentation seam з даними чернетки та захищеними admin derivatives, без мутації публікації.
3. Додати перемикання uk/en та мобільної/широкої рамки. Повернення зберігає стан редактора й позицію прокрутки.
4. Відображати поточну збережену версію; за зміни версії вимагати оновити preview, а не змішувати його з новими правками.
5. Для неповної чернетки показати явні заглушки відсутніх блоків або конкретні причини недоступності. Не передавати неповні дані як валідний public DTO.
6. Зберегти admin auth, no-store і відсутність публічного доступу, індексації та кешування приватних даних.

## Критерії приймання

- [ ] Preview відтворює сторінку сайту, а не технічний список полів.
- [ ] Save-and-preview показує саме щойно збережену версію.
- [ ] Публічне портфоліо залишається на опублікованому snapshot.

## Межі

Не створювати загальнодоступне посилання на чернетку й не додавати нову систему авторизації.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.
