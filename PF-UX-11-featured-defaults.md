# PF-UX-11 — Добірки історій без повторного введення

**Статус:** Заплановано.
**Залежить від:** PF-UX-10.
**Порядок і правила:** [PF-UX-00](PF-UX-00-INDEX.md).
**Вимоги:** [UX-план](docs/portfolio-content/admin-ux-plan.md).

## Початок роботи

Прочитати індекс перед змінами. Орієнтири для огляду актуального коду: HomeFields, home draft DTO, readiness/public mapper, preview і contracts.

## Обсяг

1. Для нового елемента добірки початково використовувати наявний опис/підпис історії та її обкладинку; явно визначити одне поле-джерело підпису й зафіксувати це в документації.
2. Власні значення відкривати через «Інший підпис або фото для головної». Не вимагати повторного введення за відсутності override.
3. Визначити семантику fallback: під час публікації головної брати дані тільки з опублікованої версії історії; публічне читання не підтягує її чернетку.
4. Зберегти наявні підписи й фото як overrides; додати явне повернення до значень історії.
5. Узгодити DTO, snapshot, preview, залежності та повторну публікацію головної після зміни історії. Додати мінімальні зміни без міграції архітектури.

## Критерії приймання

- [ ] Додати історію на головну можна без повторного введення її даних.
- [ ] Наявні власні підписи/фото залишаються чинними.
- [ ] Джерело даних і потреба повторної публікації головної зрозумілі користувачу.

## Межі

Не змінювати опублікований вигляд головної автоматично внаслідок редагування чернетки історії.

## Перевірки

За вказівкою власника запуск тестів, lint, typecheck, build і браузерне QA відкладено до [PF-UX-14](PF-UX-14-final-acceptance.md). На цьому кроці — огляд коду й diff та запис сценаріїв для фіналу. Критерії вище описують цільову поведінку; їх остаточне підтвердження виконується у PF-UX-14.
