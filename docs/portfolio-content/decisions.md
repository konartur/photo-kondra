# Підтверджені рішення портфоліо

**Дата:** 2026-11-20. **Стан:** підтверджено власником після двох раундів квізу та фінального підсумку. Цей запис замінює попередні робочі припущення; код ще не реалізовано.

| Питання | Підтверджене рішення |
| --- | --- |
| Межі | Лише портфоліо; чинні приватні галереї Photo Cloud незалежні |
| Модель | Один напрям зйомки містить багато історій; ціна належить напряму |
| Редагування | Збереження чернетки не змінює вже опубліковану версію |
| Slug | Після першої публікації незмінний |
| Видалення | Використаний контент захищений; спочатку прибрати активні посилання |
| Фото історії | До 10 унікальних фото разом з cover; дозволено менше |
| Загальна кількість | Фіксованого продуктового ліміту немає; база MVP — 21 унікальне фото, надалі зростає |
| Вхідний файл | JPEG, PNG, WebP; до 20 МБ |
| Видача фото | Полегшені WebP 480/960/1600 px, lazy loading поза першим екраном |
| Кеш | Обов’язковий Redis для published контенту; admin/preview читають DB |
| Інвалідація | Publish/archive одразу змінює кеш; TTL, version fence та надійні повтори |
| Redis outage | PostgreSQL fallback без показу архівованого stale кешу |
| MVP-імпорт | Усі існуючі тексти, ціни, фото, порядок, добірки й шість URL |
| Демофото | Усі 21 фото імпортуються з Unsplash у наше storage через media pipeline |
| Реальні матеріали | Наповнюємо через готову адмінку наприкінці; не блокують структуру MVP |

## Перевірена база фото

[media-inventory.json](media-inventory.json) відображає фактичний source-контент:
love — 4, portrait — 4, family — 3, events — 3, brand — 3, pets — 4. Разом 21 унікальне фото. Головна використовує ці самі кадри; mobile/desktop crop та responsive variants не рахуються як нове source-медіа.

Це базова кількість імпорту, а не квота. Приймання має також додати нову історію/медіа понад 21, не перевищуючи 10 у кожній історії.

## Технічне уточнення для реалізації

20 МБ визначено як 20 000 000 байтів. Якщо cover повторно використовує фото серії, mediaId рахується один раз; перевірка cover+photos атомарна. Менший оригінал не збільшувати до 1600 px.

TTL Redis 60 секунд — стартове конфігуроване значення, а не незмінна продуктова вимога. Pixel limit/quality/цільову вагу похідних підібрати й перевірити на зображеннях під час медіатікета; не знижувати якість довільно заради непогодженого жорсткого byte budget.

Реалізаційна специфікація — [архітектура](architecture.md), [DTO](dto-architecture.md), [11 послідовних тікетів](tickets/README.md). Деплой не є частиною цього підтвердження.
