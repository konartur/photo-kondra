# Локальний імпорт демопортфоліо

Імпорт використовує [маніфест v1](demo-import.v1.json) та звіряє шість slug, порядок і 21 ID джерела з [інвентаризацією](media-inventory.json). Перший кадр кожної історії стає обкладинкою. Решта кадрів відображаються в початковому порядку. Фото добірок, hero та контактного сектора повторно використовують медіа зі списку. Мобільний hero має окрему точку кадрування.

Мапінг містить початкові тексти та англійський переклад. Ціна 3 000 грн за 60 хвилин збережена як 300000 копійок. Текстові заглушки контактів залишаються текстом у вступі бронювання. Імпорт не створює контактних посилань. Для головної допускається порожній список контактів.

## Підготовка і dry-run

Команди з кореня репозиторію:

```powershell
npm --prefix backend run prisma:generate
npm --prefix backend run portfolio:import-demo -- --dry-run
$assets = Join-Path $env:TEMP 'photokondra-demo-assets-v1'
npm --prefix backend run portfolio:import-demo -- --fetch-assets --assets $assets
npm --prefix backend run portfolio:import-demo -- --dry-run --assets $assets
```

Підготовка звертається до вказаних у маніфесті оригіналів Unsplash. Підготовлений файл названий за SHA-256. Окремий JSON для кожного asset містить URL, SHA-256 завантаженого та підготовленого файла, розмір, MIME і параметри перетворення, якщо воно потрібне. Файл понад 10 МБ або 40 МП проходить обмежене зменшення до JPEG. Відсутній або пошкоджений вхід перериває імпорт. Dry-run перевіряє план і, якщо передано каталог, усі чеки та байти. Мережеві сервіси йому не потрібні.

## Запис і публікація

Потрібні окрема локальна мігрована БД із суфіксом `_demo` або `_test`, порожній приватний бакет із суфіксом `-demo` або `-test` на локальному S3 endpoint і UUID локального адміністратора. CLI отримує цілі лише з процесного середовища.

| Змінна | Призначення |
| --- | --- |
| `PORTFOLIO_IMPORT_DB_URL` | URL локальної PostgreSQL із виділеною БД |
| `PORTFOLIO_IMPORT_S3_ENDPOINT` | Loopback origin окремого S3 endpoint |
| `PORTFOLIO_IMPORT_S3_BUCKET` | Окремий приватний бакет |
| `PORTFOLIO_IMPORT_S3_ACCESS_KEY`, `PORTFOLIO_IMPORT_S3_SECRET_KEY` | Локальні ключі тестового сховища |
| `PORTFOLIO_IMPORT_OWNER_ID` | UUID наявного адміністратора у цій БД |

```powershell
npm --prefix backend run portfolio:import-demo -- --apply --assets $assets
npm --prefix backend run portfolio:import-demo -- --apply --publish --assets $assets
```

`--apply` створює чернетки. `--publish` додатково перевіряє точну імпортовану редакцію і публікує напрями, історії та головну в цьому порядку. Стабільні UUID прив’язані до маніфеста v1. Повтор використовує готові записи. Чужий slug, видалене медіа або невідповідність SHA-256 зупиняє імпорт. Вже збережені чернетки не перезаписуються. Повторна публікація після ручного редагування потребує дії в адмінці. Якщо імпорт перервався, повторіть команду з тим самим підготовленим каталогом та власником. Для медіа з активним lease дочекайтеся завершення його строку перед повтором.

## Локальне перемикання

Під’єднайте локальний backend до демо БД, того самого бакета та виділеного Redis. Запустіть Next.js з локальним `API_URL` та `PORTFOLIO_CONTENT_MODE=DB`. Перевірте головну, шість історій, обидві мови, порядок, медіаредиректи та `/sitemap.xml`. Для повного набору SEO потрібен дійсний HTTPS origin у `APP_URL`. Перед зміною джерела реального сайту потрібне окреме приймання.

Для відкату змініть серверний `PORTFOLIO_CONTENT_MODE` на `FILE` і перезапустіть frontend. Дані, фото та опубліковані snapshots залишаються в локальних PostgreSQL і storage. Після приймання джерело FILE та перемикач видаляються окремим кроком, щоб зміна була придатною до перевірки.

Для автоматизованого локального smoke можна запустити `node backend/test/portfolio-demo-storage.mjs`. Це тимчасовий HTTP fixture з об’єктами в RAM, бакетом `photokondra-import-demo` і портом 19090. Його процес має працювати протягом усієї перевірки. Для довготривалого локального стенда використовуйте приватне сумісне сховище з постійним volume.

## Приймання на production build

Production BFF приймає лише HTTPS-редиректи до сховища. Для локального тесту створіть тимчасовий сертифікат із SAN `IP:127.0.0.1`. Передайте шляхи до ключа і сертифіката у `PORTFOLIO_DEMO_TLS_KEY` та `PORTFOLIO_DEMO_TLS_CERT` і запустіть `node backend/test/portfolio-demo-storage.mjs --tls-proxy`. Fixture на 19090 лишається запущеним, а проксі на 19443 використовує ті самі об’єкти.

На локальному API задайте `API_HOST=127.0.0.1`, `PORT=19300`, `NODE_ENV=production`, `AWS_S3_ENDPOINT=https://127.0.0.1:19443` і `NODE_EXTRA_CA_CERTS` із шляхом до PEM. Решта параметрів API мають вказувати на імпортовану демо БД, окремий Redis і тестовий бакет. Зберіть frontend з `PORTFOLIO_CONTENT_MODE=FILE`, а під час `next start --hostname 127.0.0.1 --port 19301` задайте `PORTFOLIO_CONTENT_MODE=DB`, `API_URL=http://127.0.0.1:19300` і тестовий HTTPS `APP_URL`. Використайте той самий локальний `BFF_TRUST_SECRET` для API, frontend та команд нижче.

```powershell
node backend/test/portfolio-demo-acceptance.mjs
node frontend/test/portfolio-perf.mjs
```

Перша команда також читає `NODE_EXTRA_CA_CERTS` і `PORTFOLIO_DEMO_ACCESS_TOKEN` локального адміністратора. Вона створює синтетичну історію й медіа в демо БД та архівує опубліковану історію після перевірки. Друга команда вимірює локальний production build у Chromium із холодним кешем браузера. HTTPS fixture не перевіряє підпис і реальне закінчення строку дії URL. Підпис та TTL можна повноцінно прийняти на приватному S3-сумісному бакеті.
