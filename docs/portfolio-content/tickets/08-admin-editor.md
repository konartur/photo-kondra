# PF-CONTENT-08 — Керування портфоліо в чинній адмінці

**Статус:** Реалізовано локально. **Область продукту:** лише портфоліо.
**Залежності:** PF-CONTENT-07; backend готовий після PF-CONTENT-06. Порядок і посилання — у [індексі](README.md).

## Мета та область роботи

/dashboard/portfolio/*; чинний auth/BFF; editor forms/media/order/preview.

## Інструкції агенту

Прочитати [спільні правила](README.md#правила-виконання), [архітектуру](../architecture.md) і [DTO-специфікацію](../dto-architecture.md).

1. Додати окрему навігацію портфоліо в dashboard без зміни gallery workflow; при UI роботі застосувати ui-ux-pro-max і локальні Next.js docs.
2. Побудувати форми напрямів, історій, головної/контактів, upload і вибору медіа та порядок фото. Показати ліміт 10 на історію і вхідні JPEG/PNG/WebP до 10 МБ; загальну кількість фото не обмежувати.
3. Показувати saved draft, published version, unsaved edits і явні publish/archive; обробляти 409 version conflict без втрати введеного.
4. Preview доступний лише чинній адмінській сесії; використати admin media routes. Валідаційні помилки прив’язати до полів.
5. Сценарій зйомочної заявки залишити локальним; редактор не додає зберігання клієнтських заявок.

## Критерії приймання

- [x] Адміністратор створює контент і публікує його через одну наявну сесію.
- [x] Чернетки видно у приватному preview. Публічне портфоліо читає published DTO.
- [x] Підписи полів, keyboard reorder, upload retry та збереження введених даних при конфлікті версій перевірено.

## Перевірка

Виконати цільові перевірки поведінки, зазначені вище, та lint/typecheck/build змінених частин згідно зі спільними правилами. Записати команди, результат і невиконані критерії. Залежні наступні тікети не є виконаними фактом завершення цього.

## Поза областю роботи

Нова система ролей, користувачів, редактор довільних блоків і нова auth.

## Реалізація

- У чинному dashboard додано розділ портфоліо з редакторами напрямів, історій, головної та контактів. Редаговані тексти мають поля UK та EN.
- Медіабібліотека використовує прямий PUT у сховище та окремо підтверджує завантаження через API. Показує готовність і дає повторити завантаження чи обробку. Історії мають клавіатурний порядок фото та ліміт 10 унікальних кадрів з обкладинкою.
- Публікація й архівація використовують версію збереженої чернетки. Після конфлікту форма зберігає введене й дає звірити актуальну версію. Валідація прив’язує помилки до полів за іменем без відображення переданих значень.
- Приватний preview читає збережену чернетку потрібною мовою через чинний BFF і показує тільки admin derivative URLs.

Пройшли 63 Playwright-тести, зокрема 5 сценаріїв редактора з синтетичними API та сховищем. Пройшли 288 backend unit-тестів, 16 цільових HTTP e2e, frontend і backend lint, typecheck, build та перевірка OpenAPI. Наскрізне приймання на імпортованому контенті лишається в PF-CONTENT-09/10.
