# TD-PF-04 — Явна конфігурація метаданих та sitemap

**Статус:** Backlog; реалізація не розпочата.
**Пріоритет:** P1 — надійність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

Некоректний APP_URL мовчки прибирає canonical, Open Graph і явний дозвіл індексації портфоліо; root layout задає noindex. Share-зображення перевіряються через файлову систему.

## Область роботи

frontend/app/_portfolio/portfolio-metadata.ts; frontend/app/page.tsx; frontend/app/stories/[slug]/page.tsx; metadata routes; тести метаданих.

## Залежності

Працювати разом із ../../tickets/05-production-portfolio-content.md. Реальні share-файли залежать від [TD-PF-03](03-owned-responsive-assets.md). Динамічний контент потребуватиме узгодження з [TD-PF-12](12-database-content-design.md).

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. Розділити локальний demo-режим і режим публічної збірки. Для останнього явно перевіряти APP_URL і повідомляти про некоректну конфігурацію до випуску збірки.
2. Перевірити фактичний HTML та успадкування robots за встановленою версією Next.js; не вважати наслідок підтвердженим лише за читанням helper.
3. Додати sitemap лише з публічними головною та опублікованими історіями. Зберегти noindex приватних маршрутів; sitemap і robots не замінюють авторизацію.
4. Визначити перевірку та fallback share-зображень. За майбутнього object storage прибрати залежність від existsSync для віддалених ресурсів.
5. Тести виконувати з тестовим HTTPS-origin; фактичний домен і деплой залишаються окремою роботою.

## Критерії приймання

- [ ] Готовий HTML має очікувані canonical, robots, OG і Twitter metadata.
- [ ] Невалідний APP_URL не проходить непоміченим у режимі публічної збірки.
- [ ] Sitemap не містить /g/*, /dashboard/*, auth-маршрутів і чернеток.
- [ ] Описана поведінка за наявності й відсутності share-зображення.

## Перевірка

Матриця APP_URL: відсутній, невалідний, валідний HTTPS; головна, історія, невідомий slug, приватні сторінки; перевірка sitemap.

## Поза областю роботи

DNS, TLS, деплой і підтвердження доступності реального домену.
