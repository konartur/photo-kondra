# TD-PF-05 — Узгодити viewport та життєвий цикл мобільних ефектів

**Статус:** Backlog; реалізація не розпочата.
**Пріоритет:** P1 — надійність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

Початкові розміри задає inline-скрипт, потім PortfolioMotion; навігація та форма також слухають viewport. Розрахунки й обробники розподілені між кількома файлами.

## Область роботи

frontend/lib/portfolio-viewport.ts; frontend/app/_portfolio/portfolio-motion.tsx; portfolio-navigation.tsx; portfolio-booking.tsx; viewport-стилі.

## Залежності

Немає обов’язкових залежностей. [TD-PF-10](10-browser-coverage.md) дає ширшу браузерну перевірку; зміни root layout координувати з [TD-PF-08](08-route-resource-isolation.md).

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. Зіставити ініціалізацію до hydration та подальші оновлення; визначити одне джерело правил розрахунку висот, зберігши ранню ініціалізацію.
2. Сконцентрувати спільну логіку viewport у внутрішньому модулі; відокремити специфічні правила hero, header та клавіатури.
3. Об’єднувати часті події через requestAnimationFrame; записувати CSS-змінні лише за зміни значень. Зберегти коректне скасування кадрів і cleanup.
4. Зберегти стабільність hero під час зміни панелей Safari, обробку повороту, zoom, pageshow і видимість поля над клавіатурою.
5. Використати чинні регресійні тести як контракт поведінки; не спрощувати логіку ціною вже виправлених сценаріїв.

## Критерії приймання

- [ ] Початковий hero не змінює геометрію після hydration.
- [ ] Відкриття та закриття клавіатури не зсуває фонову сторінку.
- [ ] Повторна навігація не накопичує обробники й незавершені animation frame.
- [ ] На одному кадрі немає зайвих повторних записів незмінених viewport-значень.

## Перевірка

Чинні portfolio-home, portfolio-booking та portfolio-iphone сценарії; поворот, toolbar resize, pageshow і закриття діалогу.

## Поза областю роботи

Редизайн мобільного hero та новий глобальний state manager.
