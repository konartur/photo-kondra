# TD-PF-06 — Розділити логіку діалогу та формування заявки

**Статус:** Backlog; реалізація не розпочата.
**Пріоритет:** P1 — надійність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

PortfolioBooking поєднує діалог, focus trap, блокування сторінки, клавіатуру, перевірку полів, складання тексту й clipboard.

## Область роботи

frontend/app/_portfolio/portfolio-booking.tsx; внутрішні booking-модулі; frontend/test/portfolio-booking.spec.ts.

## Залежності

Немає обов’язкових залежностей. Спільні механізми узгодити з [TD-PF-05](05-viewport-lifecycle.md); зберегти контракт ../../tickets/04-booking-panel.md.

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. Виділити чисті функції валідації та складання повідомлення з явними вхідними даними, включно з типами зйомок і ціною.
2. Ізолювати керування діалогом, scroll lock і поверненням фокуса. Узгоджувати спільність з меню лише для поведінки, яка справді однакова.
3. Зберегти локальну підготовку повідомлення, скидання preview після редагування та ручне копіювання за недоступного clipboard.
4. Для BookingTrigger без provider зробити помилку конфігурації помітною під час розробки замість тихого no-op.
5. Перевірити cleanup при закритті, unmount і зміні маршруту; утримувати фокус лише на доступних інтерактивних елементах.

## Критерії приймання

- [ ] Зовнішнє використання BookingTrigger лишається простим; усі CTA працюють.
- [ ] Окремо перевіряються валідація і формування тексту без запуску браузера.
- [ ] Escape, Tab, повернення фокуса і відновлення прокручування збережені.
- [ ] Підготовка і копіювання не відправляють дані заявки в мережу чи URL.

## Перевірка

Чинні E2E бронювання та цільові перевірки чистих функцій, clipboard success/failure, редагування preview, unmount.

## Поза областю роботи

Автоматичне надсилання, зберігання заявок, новий booking API та зміна погоджених полів.
