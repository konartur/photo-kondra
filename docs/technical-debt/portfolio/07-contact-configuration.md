# TD-PF-07 — Єдине джерело контактів та робочі переходи

**Статус:** Конфігурація контактів і приховування відсутніх адрес реалізовані. Точні адреси й перевірка переходів із погодженими контактами залишаються відкритими.
**Пріоритет:** P0 — основна функціональність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

Футер показує span замість посилань; меню та форма містять текстові заглушки контактів.

## Область роботи

frontend/app/_portfolio/portfolio-footer.tsx; portfolio-navigation.tsx; portfolio-booking.tsx; конфігурація портфоліо.

## Залежності

Погоджені точні адреси власника. Виконувати як технічну деталізацію ../../tickets/09-portfolio-contact-links.md, а не дубль. Джерело даних узгодити з [TD-PF-12](12-database-content-design.md).

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. Задати типізоване єдине джерело контактів для футера, меню й форми; під час переходу до БД зберегти цей контракт читання.
2. Підключити лише погоджені HTTPS-профілі та mailto; канали без адреси приховати.
3. Якщо потрібні redirect-маршрути, дозволити лише фіксовані погоджені цілі, без довільного URL з параметрів.
4. Зберегти введені дані локальними; перехід відкриває канал, а користувач сам вставляє текст.
5. Після виконання узгодити статус і критерії приймання базового тікета 09.

## Критерії приймання

- [ ] В усіх трьох місцях контакти однакові та ведуть на погоджені адреси.
- [ ] Немає видимих псевдопосилань чи каналів без адреси.
- [ ] Переходи не містять персональних даних форми в URL.

## Перевірка

Перевірити href, клавіатурну доступність, відсутні канали, телефон і desktop без надсилання повідомлень.

## Поза областю роботи

Пошук/вигадування адрес власника, автоматичне надсилання й збереження заявок.
