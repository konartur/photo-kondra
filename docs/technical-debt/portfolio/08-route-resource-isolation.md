# TD-PF-08 — Ізолювати ресурси портфоліо та Photo Cloud

**Статус:** Backlog; реалізація не розпочата.
**Пріоритет:** P2 — UX і продуктивність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

Root layout підключає viewport-скрипт портфоліо на всіх маршрутах та QueryClientProvider на публічному портфоліо, яке зараз не використовує TanStack Query.

## Область роботи

frontend/app/layout.tsx; frontend/app/providers.tsx; frontend/app/_portfolio/portfolio-layout.tsx; route layouts; theme та auth-регресії.

## Залежності

[TD-PF-11](11-performance-baseline.md): спочатку базові вимірювання для оцінки ефекту. Координувати viewport із [TD-PF-05](05-viewport-lifecycle.md) і майбутні client-запити з [TD-PF-12](12-database-content-design.md).

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. З’ясувати фактичних споживачів provider, theme toggle і viewport-скрипта до переміщення.
2. Перенести специфічні ресурси у відповідні layouts/route groups, зберігши URL, ранню ініціалізацію і коректність hydration.
3. Підключати TanStack Query там, де є його споживачі; врахувати майбутню адмінку портфоліо без нав’язування provider публічним сторінкам.
4. Перевірити мову публічного документа: зараз root html lang=en, а вкладене портфоліо lang=uk. Обрати коректну схему мов без hydration mismatch.
5. Порівняти JS і завантажені ресурси до/після; за відсутності вимірного виграшу пояснити користь ізоляції.

## Критерії приймання

- [ ] Viewport-ініціалізація портфоліо не виконується на сторонніх маршрутах.
- [ ] Публічне портфоліо не отримує непотрібні provider-залежності.
- [ ] URL, auth, тема Photo Cloud, українська мова портфоліо і noindex приватних сторінок збережені.
- [ ] Є порівняння ресурсів до/після.

## Перевірка

Build, navigation між /, історією, /login, /dashboard та /g/[token]; чинні theme/auth E2E; перевірка hydration і document language.

## Поза областю роботи

Заміна auth/BFF, зміна публічних URL та редизайн.
