# TD-PF-09 — Перевірки цілісності контенту й справжніх ресурсів

**Статус:** Backlog; реалізація не розпочата.
**Пріоритет:** P1 — надійність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

Чинні UI-тести переважно підміняють або блокують зображення й не підтверджують наявність усіх реальних файлів та цілісність посилань контенту.

## Область роботи

frontend/test; контент портфоліо; тестові ресурси; засоби перевірки файлів/посилань.

## Залежності

Для повного закриття: [TD-PF-01](01-explicit-content-references.md), [TD-PF-02](02-story-photo-model.md), [TD-PF-03](03-owned-responsive-assets.md), [TD-PF-04](04-public-metadata.md) і [TD-PF-07](07-contact-configuration.md). Тестову інфраструктуру можна готувати незалежно. Для БД адаптувати перевірки після [TD-PF-12](12-database-content-design.md).

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. Перевіряти унікальні slug, валідні посилання на рекомендовані історії та кадри, існування локальних ресурсів, розміри, alt і порядок.
2. Зберегти швидкі UI-тести зі стабільними фікстурами й додати окремий сценарій із реальним набором публічних ресурсів без підміни URL.
3. Для віддаленого сховища після окремого рішення використовувати контрольований тестовий набір; не робити всю suite залежною від стороннього CDN.
4. Перевіряти визначені fallback-стани для відсутнього фото/контенту, а не лише happy path.
5. Запускати перевірки на фактичному джерелі контенту; не створювати другу копію списку історій усередині тестів.

## Критерії приймання

- [ ] Відсутній ресурс, дублікат slug і поламане посилання визначаються перевірками.
- [ ] Є сценарій успішного завантаження справжніх фото головної та історії.
- [ ] Тести не вимагають доступності Unsplash і не читають приватні клієнтські фото.

## Перевірка

Негативні фікстури для кожного порушення контракту та позитивний прохід погодженого набору ресурсів.
