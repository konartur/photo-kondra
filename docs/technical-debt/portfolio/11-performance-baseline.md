# TD-PF-11 — Базові вимірювання та бюджет продуктивності

**Статус:** локальну лабораторну базу для демо DB-портфоліо знято у [PF-CONTENT-10](../../portfolio-content/tickets/10-acceptance.md). Повтор із реальними фото та довготривале приймання бюджетів відкриті.
**Пріоритет:** P2 — UX і продуктивність.
**Джерело:** технічний аналіз портфоліо від 2026-11-20.

## Проблема

Немає зафіксованої бази LCP/CLS, обсягу клієнтського JS і передачі фото, тому ефект оптимізацій поки не виміряний.

## Область роботи

Локальна production-збірка frontend; звіт у docs; відтворювана конфігурація вимірювань.

## Залежності

Базу знімати до [TD-PF-05](05-viewport-lifecycle.md)/08, наскільки можливо. Після [TD-PF-03](03-owned-responsive-assets.md) повторити на реальних фото; після переходу на БД — на обов’язковому Redis-сценарії cold/warm/fallback та повільній мережі з базою 21 фото.

## Інструкції агенту

Спочатку прочитати [спільні правила виконання](README.md#правила-виконання).

1. Виміряти / і репрезентативну історію на production build: mobile і desktop, узгоджені viewport, network і CPU.
2. Зафіксувати LCP, CLS, transferred bytes фотографій і клієнтського JS. Для інтерактивності описати доступний лабораторний метод; польовий INP без реальних користувачів не заявляти.
3. Зберегти команду/інструмент, версію, конфігурацію, дату, ідентифікатор збірки та кілька прогонів з медіаною.
4. Позначити, чи фото реальні, demo або fixture; порівнювати до/після лише сумісні сценарії.
5. На основі бази запропонувати числові бюджети й допустимий шум. Фінальну автоматизацію порогів додавати після перевірки відтворюваності.

## Критерії приймання

- [ ] Є відтворювана база для обох маршрутів і профілів.
- [ ] Вказані LCP/CLS, JS та фото bytes з обмеженнями вимірювання.
- [ ] Результати оптимізацій можна порівняти з базою; пропоновані бюджети обґрунтовані даними.

## Перевірка

Повторити описані прогони, перевірити розкид і відсутність впливу dev mode або підміни ресурсів.

## Поза областю роботи

Підключення зовнішньої аналітики, збір персональних даних, деплой і необґрунтовані гарантії швидкості.
