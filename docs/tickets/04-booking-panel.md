# 04 — Підготувати повідомлення для бронювання

**Стан.** Панель реалізовано для головної та всіх історій. В ізольованому Chromium перевірено відкриття, вибір типу, валідацію, фокус і обидва способи копіювання. Поведінку з екранною клавіатурою на фізичному телефоні ще потрібно перевірити.

## Очікуваний результат

Відвідувач відкриває панель із головної або історії, заповнює дані, копіює повідомлення і може самостійно надіслати його фотографу через вказаний канал.

## Межі змін

Перенести поведінку форми з `DESIGN_SPEC.md` 1.5 і макета. Реальні контактні адреси додаються у 05. Автоматичне надсилання, провайдер, API та зберігання заявок поза межами запуску.

## Критерії приймання

- [x] Усі CTA бронювання відкривають ту саму за поведінкою панель. Обов’язкові ім’я, контакт і тип зйомки, необов’язкові дата та примітки. Є всі шість типів, зокрема `pets`.
- [x] Валідна форма готує повідомлення для копіювання. За недоступного буфера повідомлення можна скопіювати вручну. Текст інтерфейсу повідомляє про фактичну дію без твердження про надсилання.
- [ ] Помилки прив’язані до полів. Працюють Escape, закриття, утримання й повернення фокуса, керування прокручуванням і введення з мобільною клавіатурою.
- [x] Дані форми не потрапляють до URL, аналітики, журналів або мережевих запитів при підготовці повідомлення.

## Перевірка

У Playwright пройти відкриття з головної та `pets`, порожню і валідну форми, копіювання та відмову буфера. На мобільному перевірити клавіатуру, прокручування та закриття.
