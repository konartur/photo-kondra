# 08 — Запустити лендінг і Photo Cloud на одному домені

## Очікуваний результат

Канонічний HTTPS-домен показує готове портфоліо, адміністратор керує альбомами, а клієнти відкривають як нові, так і вже надіслані приватні посилання.

## Межі змін

Виконати погоджене перемикання, production smoke-тести й за потреби відкат за інструкцією з 06. Використовувати контрольний альбом і мінімальний набір тестових фото.

## Критерії приймання

- [ ] До перемикання пройшли `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` і релевантні Playwright/E2E сценарії. Збережено результати.
- [ ] На канонічному HTTPS-домені працюють головна, прямий URL історії, меню, панель бронювання та контактні переходи.
- [ ] Адмін входить, створює контрольний альбом, завантажує фото напряму до S3, бачить готовність і видає нове посилання на канонічному хості. Клієнт відкриває галерею, переглядає фото і скачує оригінал та ZIP.
- [ ] За первісною адресою контрольного посилання, виданого до запуску, у чистій сесії відкривається той самий альбом. Працюють прев’ю й скачування. Якщо вже є розіслані клієнтам посилання, адміністратор також перевірив одне чинне посилання з кожного попереднього хоста. Окремо підтверджено, що відкликаний або прострочений контрольний URL не віддає фото.
- [ ] Якщо зламався доступ за вже виданими URL, вхід, завантаження або видача фото, виконано погоджений відкат і повторну перевірку на попередній конфігурації. Запуск позначено успішним лише після проходження smoke-тестів.

## Перевірка

Пройти production checklist з двох чистих браузерних сесій, для адміністратора і клієнта. Повторити перевірки після завершення DNS-переходу, якщо DNS змінювався. У звіті зберегти час, хост, статус маршруту та результат без приватних URL, токенів і секретів.
